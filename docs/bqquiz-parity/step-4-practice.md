# BQQuiz parity, Step 4 Practice

Practice was restored ahead of the planned Generator migration. The integration base is `7d42d848651b9afb7291b8852c33c36023c82d81`. The [original source and build ledger](original-source.sha256) pins the standalone BQQuiz used for the audit and captures.

## Source audit and port

| Workflow | Original V5 source and observed behavior | BQSearch integration |
| --- | --- | --- |
| Opening and resuming | The active path in `src/App.tsx` opens published and saved quizzes from `LibraryV5`. It queries the `sessions` store's `by-quiz` index, resumes the newest `updatedAt`, and creates a session when none exists. The Practice back button returns to the Library. | Step 3 stopped at a read-only question list. Both Library entry points now open the V5 Practice sheet. Reopening a quiz, including after a page reload, resumes the newest session. |
| Recording | `PracticeViewerV5.tsx` renders the continuous question and answer sheet and two visible rows of Red/Yellow controls. A quizzer is selected before Correct or Error. `features/practice/practice.ts` stores original/reread attempts and word/character interruption anchors using the fields in `models.ts`. | The original rows, controls, question text and answer markup are ported. The activity log displays original/reread, C/E/NR and the interruption marker. These are Practice attempts, independent of Scorekeeper scoring. |
| Reread and corrections | Interrupted incorrect attempts move to an unmarked reread. The original labels the opposing team, but both rows could record a reread. History offers correction and removal, while the original helpers leave the derived state unchanged after either. | Reread still starts without a selected quizzer. Recording is limited to the opposing team while it is pending. Reread No Response records team context without assigning a quizzer. A correction or removal updates the affected question's status. |
| Activity and Undo | Activity follows the sheet on compact layouts and stays beside it on desktop. The original Undo restores the previous session snapshot. The original activity links use source question numbers, which can repeat in saved quizzes. | The layout and one-step Undo remain. Activity links and displayed numbers follow the quiz's stored positions. Undo saves the restored state and clears the undo slot. |
| Reset and persistence | `sessionDb.ts` stores attempts in `bqquiz-local` v3. The active viewer confirms Reset and creates a new session ID. Existing persisted sessions remain available in the same store. | Uses the same five stores and index with no schema migration. Opening an existing session leaves it untouched. Explicit scoring, corrections and Undo update the active record. Reset creates a new record and keeps the previous session and attempts. A stale tab cannot overwrite a newer session snapshot. |
| Print | The active V5 viewer offers Review print, Clean print and Print through `window.print()`. Print media in the pinned build hides controls, activity and interruption marks in both modes. | The same controls open browser print. Clean print contains the question and answer sheet. Review print includes recorded marks and the attempt history. Interactive controls and BQSearch chrome stay off the printed sheet. |
| Scripture | Reference chips open the original drawer. Standalone V5 displays the unavailable message because it lacks a verified verse source. | The same drawer uses BQSearch's verified Scripture pack for the active division, independently of the narrower Lookup study range. Invalid, missing and outside-division references receive explicit feedback. Questions without structured references say so. |
| Ordering and layout | The original viewer selects questions by filtering the global source array. In the shared synthetic saved quiz, it displayed Question 1 first even though the saved IDs start with Question 2. Original CSS switches the activity panel below the sheet at 850 px. | Published and custom quizzes use their stored `questionIds` order. Missing or ambiguous IDs get numbered slots without substitution. The original style and breakpoint are scoped to Practice. The contextual Practice heading is in the page flow beneath BQSearch's single global toolbar. |

The BQSearch Generator still saves the current way and focuses the Library's Saved Quizzes section. Starting Practice happens when a quiz opens from the Library. A full restore of a standalone five-store backup remains separate work. Historical slashes are retained with their source revision, and an anchor from an earlier question revision is identified in its attempt history.

- 154 unit tests passed across 33 files, and pack validation passed. The 20 enabled browser regression tests cover opening published and saved quizzes, layouts, Red and Yellow attempts, interruption and reread, Undo, No Response, session resume, reset with history retained, Library navigation, missing questions/references and Scripture outside a narrowed Lookup range. Desktop printed both modes to PDF in the regression test. The flag-off browser test also passed.
- The four side-by-side viewport tests compare all five seeded IndexedDB stores before and after browsing and resuming saved Practice. The storage regression exercises concurrent opens and stale writes. Other browser tests cover catalog integrity, offline reload, Lookup and Scorekeeper.
- Enabled and disabled production Pages builds and the Material Manager build were checked locally. The original source and approved catalog hashes were verified. This step is local for review.
