# Architecture notes

The public lookup is deliberately a client-only application. Search receives an in-memory array of verses and returns results synchronously; there is no fetch path in the search flow. A published pack can later be delivered as a signed static artifact or installed through a separately authorized administration workflow, but the public UI must remain able to search its local IndexedDB copy without network access.

The data model keeps `studyNumber` independent of `chapter` and `verse`. `schemaVersion` is present on seasons and packs so future pack migrations can be explicit. IndexedDB has separate `packs` and `settings` stores. The app applies division and study-range filters before searching.

PWA configuration is in `vite.config.ts`. The build emits the application shell and service worker. Phase 1 deliberately avoids server-side identity, cloud resources, and publishing capabilities.

## Interface redesign

The public screen is a utility layout: a compact toolbar, always-visible season/division/range context, a prominent search field, and dense result rows. Search results highlight matching terms and expose non-blocking reference/text copy actions. `Cmd/Ctrl+K`, Escape, arrow navigation, and Enter are handled globally. Settings and Material Manager remain secondary views. Light/dark mode is stored locally; mobile avoids auto-focus by checking for a fine pointer.

## GitHub Pages

`VITE_BASE_PATH` controls Vite's base URL. The checked-in Actions workflow sets `/bible-quiz-lookup/`, while local development uses `/`. Static JSON packs are referenced through `import.meta.env.BASE_URL`, so downloads work from the Pages subdirectory and remain portable to other static hosts. The service worker and manifest are generated by `vite-plugin-pwa` with relative start and scope values.
